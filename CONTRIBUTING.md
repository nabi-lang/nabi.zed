# Contributing to nabi.zed

The Zed extension for Nabi: languages and tree-sitter queries for `.nabi`
and `.nabion`, and a small Rust extension that starts `nabils`.

## Layout

- `extension.toml`: manifest; grammars pinned to a nabi-syntax commit.
- `languages/nabi`, `languages/nabion`: `config.toml` and queries.
  `highlights.scm` and `injections.scm` are generated by `scripts/sync`;
  `brackets.scm`, `indents.scm`, `outline.scm`, `overrides.scm` and
  `textobjects.scm` are edited here.
- `src/lib.rs`: finds `nabils` and builds its command line.
- `nabi-syntax.rev`: the pinned nabi-syntax commit.

## Development

Install Rust with rustup and the wasm target Zed builds for:

```sh
rustup target add wasm32-wasip2
cargo build --release --target wasm32-wasip2
```

In Zed, run `zed: install dev extension` and pick this checkout. After a
change, press **Rebuild** on the extension in the Extensions page.
`zed: open log` shows build and `nabils` errors; start Zed with
`zed --foreground` for more.

## Queries

Every query must compile against the pinned grammar. Check them with the
tree-sitter CLI over nabi-syntax's corpus:

```sh
git -C ../nabi-syntax checkout "$(cat nabi-syntax.rev)"
(cd ../nabi-syntax && npm ci)
scripts/check-queries ../nabi-syntax
```

Capture names follow
[Zed's list](https://zed.dev/docs/extensions/languages#syntax-highlighting).
A later pattern wins over an earlier one for the same node, as in
nabi-syntax. To change highlighting, change nabi-syntax's
`highlights.scm`, or the capture map in `scripts/sync`.

## Bumping the grammar

1. Land the grammar or query change in nabi-syntax and push it.
2. Sync from a checkout at that commit:

   ```sh
   scripts/sync --from ../nabi-syntax
   ```

   This writes `nabi-syntax.rev`, the `rev` of both grammars in
   `extension.toml`, and the generated queries.
3. Run `scripts/check-queries ../nabi-syntax`, fix the Zed-only queries if a
   node was renamed, try it as a dev extension, and commit.

CI runs `scripts/sync --check`, the query check and the wasm build.

## Submitting

Open a pull request against `main` with the CI checks above passing. By
contributing you agree that your work is licensed under both MIT and
Apache-2.0, the project's dual license.

## Releasing

The version in `extension.toml` and `Cargo.toml` is independent of the Nabi
toolchain. Bump both, add an `## X.Y.Z` entry to `CHANGELOG.md`, commit on
`main`, then open a pull request against
[zed-industries/extensions](https://github.com/zed-industries/extensions)
that adds or bumps the `extensions/nabi` submodule and its entry in
`extensions.toml`.

## Sign your work

Nabi uses the [Developer Certificate of Origin 1.1](https://developercertificate.org/)
(DCO) instead of a CLA. By adding a `Signed-off-by` line to a commit you
certify that you wrote the change, or otherwise have the right to submit it
under this repository's license. `git commit -s` adds the line:

```text
Signed-off-by: Your Name <you@example.com>
```

Use your name and an email you can be reached at; the email must be the
commit's author email. The `DCO / Check sign-off` check fails a pull request with an
unsigned commit. To fix it, run `git commit --amend -s` (last commit) or
`git rebase --signoff main` (every commit), then push again. The full text
of the DCO is in the
[organization's CONTRIBUTING.md](https://github.com/nabi-lang/.github/blob/main/CONTRIBUTING.md#developer-certificate-of-origin).
